# Static review sweep

A one-off pass over every non-test source file, fixing the eight defect classes found in
`src/app/facade.ts` on 2026-08-15. **This file is scaffolding, not doctrine** — it is a worklist
that gets checked off and then deleted. Nothing here overrides [AGENTS.md](../AGENTS.md); it is a
lens for applying it uniformly.

## Rules of the sweep

1. **Fix as you read, except across files.** Classes A, B, E, F, G and H are answerable inside one
   file: find and fix in the same pass. Classes C and D span files by definition — record them in
   the ledger and fix them in wave 2, never opportunistically from inside one file's pass.
2. **The gate is the unit of done.** `./scripts/fix` then `./scripts/check`, clean, before every
   commit. Read its output whole.
3. **A behaviour change gets a test that fails without it** (definition of done). A class F or G fix
   changes behaviour and needs one. A class B or H fix is a move — no new test, but the existing
   suite must pass untouched, and if it doesn't the move wasn't a move.
4. **Smallest change that solves the problem** (principle 4). No drive-by renames, no reformatting
   outside the fix, no improving code you happened to read. A file's pass fixes the classes and
   stops.
5. **Cite `path:line`** in every ledger entry and commit body. A finding without a line number is an
   opinion.
6. **Style is out of scope** (principle 8). If oxfmt or oxlint enforces it, it is not a finding.
7. **A waiver with a good reason is not a finding.** [0007](decisions/0007-reviewed-oversized-functions.md)
   makes oversized functions legal _when waived at the site with a reason_. Fix the missing reason,
   the stale reason, or the reason that does not survive contact with the code — not the waiver's
   existence.
8. **When a fix is a judgment call, stop and ask.** Class B extractions create files and move public
   surface; if the host file's own comment argues against the split, that argument gets answered by
   a human, not overruled by an agent.

## The taxonomy

Eight classes, derived from the facade review. Each is a question to ask of a file, the principle
or doc it comes from, and how to spot it. Name findings by class so the totals mean something.

**Which wave fixes which class** — the split that shapes everything below:

| Class            | Scope                | Fixed in                  |
| ---------------- | -------------------- | ------------------------- |
| A, B, E, F, G, H | inside one file      | wave 1 / 3, as it is read |
| C, D             | across several files | wave 2, from the ledger   |

### A. Over the cap, waived file-wide

`docs/map.md:121` sets a soft cap of 400 lines and a hard cap of 800. A file-wide
`// oxlint-disable max-lines` silences the gate permanently, so the file can never tell you it grew
again — which is the opposite of what [0007](decisions/0007-reviewed-oversized-functions.md) asks
for (waive one at a time, at the site, with a reason).

**Ask:** is the file over 400? Over 800? Is the waiver file-wide or per-site? Does the stated reason
still describe the file?

### B. A concern that closes over nothing

The signature of a wrongly-placed block: it uses none of its host's local state. In `facade.ts` the
110 lines of wire guards touched no store, bus, or engine — so the "splitting means threading shared
state through helpers" defense, which was true of the coordinators, was false of them. They were
also the sole reason for that file's `import/max-dependencies` waiver.

**Ask:** which top-level blocks reference zero closure/module state? Which imports exist _only_ to
serve one such block? Extracting the block usually retires a lint waiver too.

### C. Third occurrence reached

Principle 3: DRY on the third, not the second. Two copies are correct and should be left alone —
report them as **watch items** so the third one is recognisable when it lands.

**Ask:** what three-line-plus shape appears three times? In `facade.ts` it was the
`repository === null ? new Map() : await repository.blobs(...)` triad.

### D. One fact declared more than once

Principle 1. Distinct from C: not a repeated _shape_ but a repeated _fact_ — a set of names, a list
of cases, a constant. In `facade.ts` "which commands are groupable" existed three times: a type
union, a boolean record, and a twelve-branch `!==` chain. The `satisfies` check caught a missing key
but not a divergence between the three.

**Ask:** if this list gains a member, how many places must change? Does the compiler catch it if one
is missed, or does it fail at runtime?

### E. A flag or cleanup written on every exit path

`grouping = false` at four sites in one function. Each is correct today; a fifth branch added later
is not. `try/finally` writes it once.

**Ask:** is any mutable flag assigned more than twice in one function? Is every early return and
catch accounted for?

### F. A guard that runs once when it should run always

`peek()` checked deck membership only on the first read, because the scratch cache short-circuited
it — so a removed deck returned zeros headlessly (principle 5's silent fallback) and a foreign error
message with an engine. Caching a _value_ is fine; caching past a _check_ is the bug.

**Ask:** does any memoised/lazily-initialised path skip a validation the cold path performs?

### G. Silent fallback / swallowed failure

Principle 5. `?? 0`, `?? null`, empty `catch`, a default that stands in for a missing value. Some
are correct and documented (`peaks()` returning null before first load). The distinction is whether
a caller can tell "absent" from "broken".

**Ask:** for each fallback, what does it hide, and would the user or log ever learn?

### H. Inconsistent placement of like things

In `facade.ts`, four coordinators were hoisted consts and five comparable ones sat inline in the
returned object literal — a reader cannot predict which. Not a defect; a tax on every future read.

**Ask:** are things of the same kind in the same place in this file, and in its neighbours
(principle 2)?

## Mechanical pre-pass

Run once, whole. These findings are free and should be recorded before any file is read, so a
reading pass can spend its attention on B, D, F, and G — the classes no grep can find.

```sh
# A — size, against the 400 soft / 800 hard caps
find src \( -name '*.ts' -o -name '*.tsx' \) ! -name '*.test.*' ! -path 'src/ui/components/*' \
  | xargs wc -l | sort -rn | head -30

# A — file-wide waivers (the ones that silence the gate forever)
rg -n 'oxlint-disable ' src --glob '!*.test.*' --glob '!src/ui/components/*'

# A — per-site waivers, by rule and file
rg -o 'oxlint-disable(-next-line)? ([a-z0-9/_-]+)' -r '$2' src \
  --glob '!*.test.*' --glob '!src/ui/components/*' | sort | uniq -c | sort -rn

# G — fallbacks and swallows
rg -n '\?\?|catch \(|catch \{' src --glob '!*.test.*' --glob '!src/ui/components/*'

# D — exhaustive records and unions that may have a twin elsewhere
rg -n 'satisfies Record<|as const satisfies' src --glob '!*.test.*'

# E — mutable module/closure flags
rg -n '^\s*let ' src --glob '!*.test.*' --glob '!src/ui/components/*'
```

## The ledger

One file, `docs/audit-ledger.md`, appended to by every wave. It exists to hold what a file's own
pass may not fix. Entries look like:

```markdown
- **D** — the groupable-command set, declared 3× —
  `commands.ts:61`, `facade.ts:87`, `facade.ts:132` — a `satisfies` catches a missing key but not a
  divergence between the three. Found in wave 1 (`facade.ts`).
```

Nothing else goes in it. A class A/B/E/F/G/H finding is fixed in the pass that found it and lives in
the commit, not the ledger; writing it down twice is the thing this sweep exists to delete.

## Commit protocol

- **Wave 1: one commit per file.** A file's fixes are one coherent change and the gate proves it.
- **Wave 2: one commit per fact**, however many files it touches. That is the unit that is
  reviewable as a single idea.
- **Wave 3: one commit per directory.**
- Commit bodies name the class and the `path:line` fixed. `git log` is then the sweep's report, and
  no findings document has to survive.

## Stop rules

- **A file's pass is capped at its own findings.** If a fix wants a fix elsewhere, that is a ledger
  entry, not scope creep.
- **A class with one instance is a fix. A class with eight is a habit** — and the fix is a rule: an
  ADR in `docs/decisions/`, as long as the decision is and not a line longer. Do not write the ADR
  before the count justifies it.
- **Abandon wave 3 if wave 1 yields nothing but class H.** The long tail is 72 small files that
  probably are what they look like, and finishing a checklist is not a reason to touch them.
- **Delete this file and the ledger** in the last commit. Whatever survived lives in
  `docs/decisions/` or in the code.
