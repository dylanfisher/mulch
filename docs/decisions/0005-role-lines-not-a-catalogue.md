# 0005. The catalogue is a grep, not a document

- **Date:** 2026-08-12
- **Status:** accepted

## Context

Agents duplicate code for one reason above all others: they cannot cheaply answer "does this
already exist?" before writing. `docs/map.md` answers _where things go_, and answers it well, but
it deliberately holds no inventory — an inventory is a second copy of facts the code already
holds, it rots within a week, and nothing fails when it diverges.

The obvious fix is the pattern many React codebases land on: a hand-maintained `architecture.md`
with a per-component catalogue — _what / use when / instead of_ for every file. It works, briefly.
Then it is maintained by hand, so it drifts, and drifted entries are worse than none: they read as
authoritative. It is also expensive — thousands of tokens read to answer one question about one
component.

## Decision

Every file under `src/` carries its own one-line `@role` (plus an optional `@instead` pointing at
what someone would otherwise duplicate). `./scripts/map` greps them into the catalogue, and
`./scripts/map --check` runs as the `roles` step of `./scripts/check`, so a file without one does
not reach `main`.

`src/ui/components` is exempt — it is regenerated by `shadcn add`, which would erase the line —
and is indexed by its exports instead. The gallery at `#/dev` is the version you look at.

## Alternatives considered

- **A hand-written catalogue in `docs/map.md`** — rejected. It restates what the code says, has
  no failure mode when wrong, and costs a full read per question. This is the thing `map.md`'s
  own preamble forbids, and the reason it forbids it.
- **Rely on `rg` alone** — rejected as insufficient, not wrong. Grep finds a name you can already
  guess; it does not tell you that `Knob` is the thing you wanted when you searched "dial". The
  `@role` lines make the corpus searchable in the terms of what things _do_.
- **A generated catalogue committed to the repo** — rejected. A committed generated file is a
  cache, and a cache needs its own staleness check. Generating on demand costs one command.
- **Requiring `@role` in `src/ui/components` too** — rejected. It would be silently erased by the
  next `shadcn add`, which trains everyone to ignore the check. See `0003`.
- **Richer tags (`@use-when`, `@wraps`, `@see`)** — rejected for now. `@instead` is the one that
  prevents duplication; the rest is prose that belongs in the docblock. Add a tag when a third
  file needs it (principle 3).

## Consequences

- The catalogue is complete by construction and cannot silently drift: the check fails on a
  missing `@role`, and on an `@instead` naming a path that has moved.
- The tier list now lives in exactly one place — the `<!-- paths: -->` line in `docs/map.md`,
  which `scripts/map` reads. `scripts/arch` still keeps its own copy, because it needs the edges
  and not just the nodes; collapsing those two is the obvious next step if a third reader appears.
- Adding a file costs one extra line. That is the price of the index, and it is paid by the person
  who knows the answer, at the moment they know it.
- Reading the catalogue is one command and a few hundred tokens. `./scripts/map src/audio` narrows
  it to a tier, which is the escape hatch if `src/` grows past what fits on a screen — the answer
  is never a return to a written catalogue.
