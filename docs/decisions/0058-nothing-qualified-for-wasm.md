# 0058. Nothing qualified for WASM, and it was not for lack of headroom

- **Date:** 2026-08-16
- **Status:** accepted

There is no Rust and no second language in the build. The three candidates were measured with `./scripts/bench` — a plain-Node kernel bench, on demand, never in the gate (0050) — as means ± stdev across 11 timed runs after one warm-up, over synthesised stereo 48kHz sources with transients twice a second, at 30s, 3min and 10min. The third candidate has no code to measure: key lock shipped as nothing at all (0031).

`analyzeBeats` costs 2.2ms / 13.1ms / 45.6ms and `peaks` 2.7ms / 9.8ms / 31.3ms at the 2048 columns `src/app/engine.ts` asks for, 1.9ms / 9.6ms / 30.7ms at the 1200 `src/app/render.ts` asks for. Beside them the bench times two probes over the identical arrays: a scalar scan doing one add per sample (1.7ms / 10.1ms / 33.8ms) and a strided scan touching one float per 64-byte cache line (0.3ms / 0.7ms / 2.4ms). The gap between those two is the finding. Streaming all 220MB costs 2.4ms; touching every sample in it costs 33.8ms. These kernels are bound by per-sample instruction throughput, not by memory traffic, which is exactly the bound a wider instruction set attacks — so the headroom a SIMD port would go after is real, and an earlier draft of this record claiming the kernels were at the speed of moving samples was wrong.

They are rejected on absolute cost instead. 13.1ms measures a 3-minute source, and it is spent in `src/workers/analysis.ts`, off the thread that paints, on a result no gesture awaits; `peaks()` runs once per decode in `src/app/engine.ts` and once per offline PNG in `src/app/render.ts`, never on the frame loop. Nothing here is on a frame deadline, and the best imaginable port takes a load-time 9.8ms to something under 3ms — a win no one can feel — against a crate, a build step in `./scripts/setup` and the Vite build, and a toolchain a fresh clone must install, which is well past the 250ms step size (0012). The bar for the work still pointing at this is therefore absolute milliseconds on a path someone waits on, not the existence of headroom: every kernel in this instrument has headroom, and that is not the question.
