# 0360 — A run is a tear, and its knobs are what the tear is like

- **Date:** 2026-09-11
- **Status:** accepted, extending
  [0296](0296-the-automator-shards-the-picture.md) and
  [0298](0298-every-automator-tears-the-torn-picture.md) under
  [0359](0359-a-value-reaches-the-picture-through-a-row-or-a-look.md)

0296 said the shards were the one look with no terms at all: how torn the picture is, is how many
automators stand, which is a fact about the run each of them _is_ and not about any value one
holds. That was true of _how much_ and wrong about _what it is like_. Seventeen of the automator's
knobs stood outside the picture behind it.

**Eleven of them are already reached, and now say so.** A pool weight decides which effects a run
grows, and every effect a run grows is a row of its own the moment it arrives. So `AUTO_UNREACHED`
is the eleven weights, with the grown rows named as their reach — not a silence, and not a row per
weight for a pool the run may never draw from.

**The six that shape the run are the look's terms.** `seed` is which valley the tear reads, so two
automators on two seeds tear two planes rather than one plane twice; `least` is how far into the
structure it reads, a run that is never empty being torn from inside one place rather than across
the whole sweep, which is larger pieces and not finer ones; `odds` is how much of the picture is
torn at all, a piece outside the share standing where it was — floored at a quarter, because the
run's floor beats the odds and a run at no odds is still standing, still holding its Least and still
audible, so a picture that tore none of it would say no automator was there; `wait` is how far apart the seams
stand, a run nothing is being laid in having stopped splintering; `fade` is how much of the reach
still stands, a run always half-arrived being a seam half open; and `wander` is the scatter turn
itself, which stays an irrational share of the circle at every setting so no setting of it is the
wave 0297 refused. Every term absent is the tear exactly as 0296 and 0298 shipped it.

**And the hourglass is the moment's, not a knob's.** `DeckPeek.waits` — how much of a hold is still
to run — is written onto the look beside `held`, per frame, and turns that automator's whole layer
half a turn at a hold of a passage or longer, back to nought as it empties. **Read against its own
band and not the knob's**: a hand may ask for ten minutes, and a hold read as a share of that would
move the picture a fortieth of a turn for the half-minute hold somebody actually takes. A wait counting down is the tear
closing. `auto.wait` therefore reaches the picture twice and honestly: the length a hand asked for
is a term, and how much of it is left is a fact about now, which is the same split `held` already
made against `most`.

**`fractalRest` takes a seed**, defaulting to the notch it always answered with, so where a run
stands along the valley is one arithmetic and not two. The valley holds nine stops each way, read
off the fold above the bits the rest of the picture spends (0076), so two seeds are two of
eighty-one valleys and not two of a continuum — and a seed nudged by less than a fold's own step is
a different run in the ear and the same plane in the picture, which every seeded reading in this
repo already does.

No frame cost: every term is read once a painting inside the throw table the cut already fills, no
term reaches a tile key, and the bake count is untouched ([0353](0353-the-stamp-runs-on-the-marks-bit-grid.md),
[0354](0354-the-screen-tile-is-baked-off-the-frame.md)). Durable shape: none.
