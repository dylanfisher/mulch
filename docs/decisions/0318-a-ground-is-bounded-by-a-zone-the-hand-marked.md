# 0318 — A ground is bounded by a zone the hand marked

- **Date:** 2026-09-08
- **Status:** accepted, amending
  [0183](0183-a-bed-is-the-loop-moved-and-it-is-the-transports.md)'s `bedBounds` — offset zero is no longer
  promised — and extending
  [0184](0184-the-ground-is-the-songs-and-a-part-plays-back-on-it.md): a zone is the song's, like
  every other field of the ground it bounds.

**`BedSpec` gains `zone: { from: number; to: number } | null`, in the loop's own sixteenths.** One
span and not a list: the list of places a ground returns to is already the planted beds, so a zone
is the bound and the beds are the itinerary, and a second arrangement beside them would be two
answers to where the loop goes. **Null is no zone**, which is the whole of "unbounded" — no second
flag beside it, the shape `bedEvery: 0` already has. The unit is `bedBounds`' own, because a zone
that could not be compared with what that function answers could not narrow it.

**The yard's own and never the session's.** A sixteenth is a sixteenth _of this yard's loop_, so one
shared zone would name a different region of every file — which is not what "only here" says. That
is the opposite answer to the one 0313 gives the crawl itself, and the units are the whole reason.

**It narrows `bedBounds` and nothing else changes.** Each edge is pulled into the room the buffer
answers for rather than intersected with it, so a zone reaching past a short file is that file and
one wholly past its end is the nearest ground the file holds — never an empty pair nothing could be
folded onto. Because every reader of a ground already comes through that one function, a drawn
crawl, a planted bed and the shared ground a Together yard reads all land inside the zone by the
same arithmetic, and no reader asks whether a zone exists.

**And it is heard where it is turned.** The bounds a pass is laid against are answered once at
`begin`, which was true while they were the buffer's alone; a zone is the one input to them a hand
moves mid-pass, so `player.set` re-answers them beside the re-arm every moved number already takes
(`zonedGrid`, src/audio/playerGrid.ts). Without that the picture folds and the sound does not, which
is the disagreement `slotStart`'s own doc exists to refuse.

**Zero is no longer promised.** A zone marked at the far end of a file does not contain the loop, so
`bedWrap` folds a home roll — a yard's own `bed`, or the shared ground's zero — onto the zone the
way it folds anything else. Coming home means the nearest home inside the zone. That is the honest
reading of a hand that said "only here", and the doc that promised otherwise is amended rather than
worked around.

**The loop's own window is not folded.** Every block on the ground strip is a ground the walk may
reach except one: the marker that says where the loop itself is, which is a fact about the deck and
the reference every other block is read against. Folded, it would claim the loop is somewhere the
loop handles and the waveform both say it is not.

**A hand marks it on the strip, not on a dial.** Two edges are a place and not an amount, so there
is no `PLAYER_SONG_KNOBS` row and no `copyKnobs` caption: a Shift-drag on src/ui/PlayerGround.tsx
sweeps the span out of its own two ends, its two edges are dragged the way the loop's own handles
are, and a Shift press that never travelled clears it back to the whole file.
