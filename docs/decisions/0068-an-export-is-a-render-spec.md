# 0068. An export is a spec for the one render harness

- **Date:** 2026-08-16
- **Status:** accepted; rests on [0026](0026-pre-release-has-no-migrations.md) and the one-signal-chain boundary

Audio leaves the app as a `RenderSpec` and nothing else. `File → Export Audio` collects four things — a name, a length, and a fade at each end — and `exportAudio` turns the live session into exactly the commands `restorationCommands` already hydrates a reload with, plus one `deck.play` for each yard whose transport is running, and hands them to `renderOffline`. There is no second renderer, no export-only graph and no export-only scheduling: what the file contains is what the harness renders, which is what the live/offline pair is already proved through, so ten minutes exported is the ten minutes that would have played. An export spec is not session state — no command, nothing durable, no history entry — and the length the dialog pre-fills is read from the session at the moment it opens.

Three things follow. A render may be handed the session's blobs, because a render builds its own instrument and one with no storage refuses to load an imported source; the harness wraps them in an in-memory repository that is discarded with the render, so a render can never write to the storage the live session owns. Because a stored source decodes asynchronously, the harness now delivers its envelopes serially across a load in flight, exactly as startup restoration does — a synchronous pass would have every command after a `deck.load` refused as unloaded and would render an imported yard as silence, and an export therefore reads its own render's log back and refuses to hand over a file the render reported an error for. And the fade is arithmetic over the rendered samples (`src/lib/fade.ts`), applied before the fingerprint and the encoding, rather than a gain node in the chain: a fade belongs to the file, not to the instrument, and putting it in the graph would mean the exported buffer and the played one differ by a node the performance never had.
